# 智能学习助手 - 项目说明（大白话版）

---

## 一、这个项目是干什么的？

一句话：**一个 AI 学习助手网站**，学生可以在上面：
- 和 AI 聊天，问学习问题
- 上传 PDF 学习资料，AI 帮你检索相关内容
- 让 AI 帮你制定学习计划、讲解概念、出练习题

## 三、核心技术原理（重点！）

### 3.1 整体架构

```
用户在网页提问
    ↓
前端（app.py）把问题传给后端的智能体
    ↓
智能体（react_agent.py）开始 ReAct 循环
    ↓
智能体把问题 + 工具说明 一起发给大模型
    ↓
大模型自己决定：直接回答？还是调工具？
    ↓
调了工具 → 拿到结果 → 再问大模型 → 够了吗？→ 够了就回答，不够继续调
    ↓
最终回答返回给前端展示
```

### 3.2 ReAct 是什么？

ReAct = **Re**asoning（推理）+ **Act**ing（行动）

就是一种让 AI "边想边做" 的方法：

```
第1步（思考）：用户问了"列表推导式是什么"
              → AI 想：这是一个概念讲解的需求，我应该用 explain_concept 工具

第2步（行动）：调用 explain_concept 工具，参数是 {concept: "列表推导式"}

第3步（观察）：工具返回了详细的讲解内容

第4步（判断）：AI 看了工具返回的内容，觉得信息够了
              → 整理成最终回答给用户
```

**关键区别**：
- 以前的做法：代码里写死规则，看到"解释"两个字就调解释工具（关键词匹配）
- 现在的做法：把工具的"说明书"给 AI 看，让 AI 自己判断要不要用、用哪个

### 3.3 Function Calling（函数调用）机制

怎么让 AI "自己决定" 调工具的？

靠的是大模型（qwen-max）自带的 **Function Calling 能力**。

具体做法：
1. 我们把工具的定义（名字、描述、参数）用固定格式发给大模型
2. 大模型看到问题后，有两种选择：
   - 不需要工具 → 直接返回文字回答
   - 需要工具 → 返回一个特殊格式，告诉我们"我要调用 xxx 工具，参数是 xxx"
3. 我们执行工具，把结果再发给大模型
4. 大模型看到结果后再决定：够了就回答，不够就继续调

```python
# 这一行就是"把工具说明书绑到 LLM"
self.llm_with_tools = self.llm.bind_tools(self.tool_schemas)

# 这一行就是"问大模型，让它决定"
response = self.llm_with_tools.invoke(messages)

# 这一行就是"看大模型有没有决定调工具"
if not response.tool_calls:    # 没调 → 直接回答了
    ...
else:                          # 调了 → 执行工具
    for tc in response.tool_calls:
        result = execute_tool(self, tc["name"], tc["args"])
```

### 3.4 RAG（检索增强生成）是什么？

RAG = Retrieval-Augmented Generation（检索增强生成）

简单说就是：**先从知识库找到相关内容，再让 AI 基于这些内容回答**。

```
用户上传 PDF
    ↓
PDF 被切成小段 → 每段转成向量（一串数字）→ 存到 FAISS 向量库

用户提问："Python 的循环怎么写？"
    ↓
问题也转成向量
    ↓
在 FAISS 里找和问题最接近的文档片段（相似度搜索）
    ↓
找到的内容 + 用户问题 一起发给 AI
    ↓
AI 基于找到的内容来回答（而不是凭空编造）
```

为什么用 FAISS？
- FAISS 是 Facebook 开源的向量搜索库
- 把文字转成数字向量后，可以用数学方法快速找到最相似的内容
- 比传统的关键词搜索更智能（"怎么写循环" 能找到 "for 语句用法"）

### 3.5 4 个工具分别干什么

| 工具 | 功能 | 什么时候 AI 会用它 |
|------|------|-------------------|
| `rag_search` | 从知识库搜索相关资料 | 用户的问题可能涉及已上传的文档 |
| `explain_concept` | 按模板讲解概念（定义/类比/例子） | 用户想理解某个概念 |
| `generate_study_plan` | 生成分阶段学习计划 | 用户想规划学习路线 |
| `generate_questions` | 生成练习题（含答案和解析） | 用户想做练习 |

每个工具本质上都是一个 **带模板的 prompt**——给大模型一个固定格式的提示词，让输出更规范。

## 四、前端页面说明

### 4.1 在线问答（QA 页面）
- 用户输入问题 → 调用 ReAct 智能体 → 显示思考过程和最终回答
- 支持流式展示（能看到 AI 每一步在干什么）

### 4.2 知识库页面（4 个标签页）
- 上传 PDF：上传学习资料，自动切片、向量化、存入 FAISS
- 文档管理：查看已上传的文档列表
- 向量搜索：直接测试关键词搜索效果
- RAG 问答：基于知识库内容的问答

### 4.3 知识讲解
- 输入概念名 → 调用 explain_concept 工具 → 显示结构化讲解

### 4.4 学习计划
- 输入学科和目标 → 调用 generate_study_plan → 显示分阶段计划

### 4.5 练习出题
- 输入主题 → 调用 generate_questions → 显示题目+答案+解析

### 4.6 思维链可视化
- 展示上一次问答中 AI 的完整推理过程
- 每一步用的什么工具、传了什么参数、返回了什么结果

## 五、老师可能会问的问题

### Q1: 为什么用 ReAct 模式而不是直接让 AI 回答？
A: 因为用户的问题类型不同。有时候需要检索知识库，有时候需要生成计划，有时候直接回答就行。ReAct 模式让 AI 自己判断需要用什么能力，比写死规则更灵活。

### Q2: Function Calling 是怎么实现的？
A: 通过 OpenAI 兼容的 API。qwen-max 支持 function calling，我们把工具的定义（名字、描述、参数格式）通过 API 传给模型，模型会自己决定是否调用工具。调用了就返回工具名和参数，没调用就直接返回文字。

### Q3: RAG 的作用是什么？
A: 让 AI 的回答有据可依。用户上传的文档会被向量化存入 FAISS，提问时先检索相关内容，再让 AI 基于检索结果回答，减少"编造"的情况。

### Q4: 为什么选 Streamlit 做前端？
A: Streamlit 是 Python 的快速 Web 框架，适合数据科学和 AI 应用的原型开发。优点是开发快、和后端（也是 Python）无缝衔接。

### Q5: FAISS 向量搜索的原理？
A: 把文本通过 Embedding 模型转成高维向量（一串数字）。搜索时，把问题也转成向量，用余弦相似度计算问题和文档片段的距离，找到最接近的结果。就像在地图上找最近的点。
