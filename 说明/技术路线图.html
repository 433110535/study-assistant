三、关键技术决策

5 个核心决策：
  • ① 自研 ReAct 循环（非 AgentExecutor）— 为事件流式输出 + 思维链可视化 + 细粒度错误控制，代价是代码量大
  • ② FAISS 取代 pgvector/Chroma — 免 PostgreSQL 安装、部署简单、本地运行快
  • ③ OpenAI 兼容接口接入通义千问 — LangChain 生态原生支持、切换模型零成本（仅改 base_url + api_key）
  • ④ 单文件 app.py（2000+ 行）— 共享 session_state 方便，代价是不利于协作
  • ⑤ 本地 sentence-transformers（非 API Embedding）— 免费、离线、中文模型够用

四、性能指标

实测数据：
  • LLM 单次响应：1-3 秒（取决于提示长度）
  • ReAct 完整循环：5-15 秒（平均 2-3 轮工具调用）
  • PDF 处理：10 页约 3 秒（切段+向量化）
  • 向量搜索：< 50ms（FAISS 内积搜索）
  • Embedding 模型加载：首次 5-10 秒（@st.cache_resource 后零延迟）

五、Harness Engineering 在哪体现

把裸模型包装成可用 Agent 的"外壳"：
  • 工具定义（react_tools.py）— 6 个工具的 Schema + Executor 双轨
  • Agent 循环（react_agent.py）— yield 事件流 + 迭代控制
  • 对话管理（base_agent.py）— 消息类型流转 + 上下文维护
  • 错误处理 — try/except 包裹 LLM 调用 + 友好错误事件
  • 迭代限制 — max_iterations=5 防 API 耗尽
这些"外壳"让 LLM 从"被动回答工具"变成"主动调度的智能体"。
